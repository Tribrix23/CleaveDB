1. FEATURE OVERVIEW & THESIS
--------------------------------------------------------------------------------
Conventional databases face the 55-year Distributed Referential Integrity Paradox:
  - Relational SQL engines (Postgres, Oracle, CockroachDB) enforce rigid, synchronous
    foreign keys. If an event or child record arrives before the referenced parent,
    the transaction aborts or requires distributed Two-Phase Commit (2PC).
  - NoSQL systems (Cassandra, MongoDB, DynamoDB) discard foreign keys entirely,
    causing "referential decay"—silent accumulation of dangling, orphaned records.
  - Graph databases (Neo4j) rely on physical pointer adjacency, crashing or failing
    when traversing unmaterialized nodes.

CleaveDB introduces the ASYNCHRONOUS REFERENTIAL FABRIC:
A storage and query architecture where relationships ("Bonds") are first-class,
autonomous state machines. Relationships can be written before target records exist
(Late Binding), latched in a low-overhead index (The Phantom Lattice), and atomically
fused into the active topology the exact microsecond the target document lands
(The Cleave-Snap Protocol).


2. MATHEMATICAL MODEL: THE BOND JOIN-SEMILATTICE
--------------------------------------------------------------------------------
A relationship in CleaveDB is modeled as an element of a bounded join-semilattice:
    <Sigma, <=, \sqcup>
where Sigma = {Bottom, Phantom, Latched, Fused, Severed, Top}.

The partial order defines the lifecycle of referential state:
    Bottom <= Phantom <= Latched <= Fused
    Latched <= Severed (Tombstone dominance)

Monotonic Convergence Theorem:
For any set of document writes D and bonds B arriving in arbitrary order:
    \forall \pi_1, \pi_2 \in Perm(W): Fold(\delta, Bottom, \pi_1) = Fold(\delta, Bottom, \pi_2)
Every write sequence terminates at the identical, consistent topological graph G(D, B)
without distributed locks or transaction aborts.


3. ARCHITECTURAL BREAKDOWN ACROSS LAYERS
--------------------------------------------------------------------------------
3.1 The Rust Storage Engine (storage/src/engine/phantom_lattice.rs)
  - `ShadowRecord`: Represents a pending bond with source GID, target GID, label,
    enforcement policy (Soft, Firm, Strict), creation timestamp, and lease expiry.
  - `LatchFilter`: A hardware-friendly 64K-bucket atomic counting filter.
    Provides O(1) hash checks on every document write with ZERO disk I/O overhead.
  - `PhantomLattice`: Thread-safe concurrent index (`DashMap<String, Vec<ShadowRecord>>`)
    mapping unmaterialized `target_gid` -> pending shadow bonds.
  - Exposes atomic telemetry counters:
    * `active_pending_latches`
    * `total_latched_bonds`
    * `total_snapped_bonds`
    * `total_expired_bonds`

3.2 The Reactive "Cleave-Snap" Protocol (storage/src/engine/operations.rs)
  - In `Database::put()`:
    1. Derives bond targets from the document body (`derive.rs`).
    2. Validates targets: if a target does not exist, Soft and Firm bonds are
       latched into `phantom_lattice` rather than aborting.
    3. Serializes and commits the document to the B+Tree and WAL.
    4. **The Cleave-Snap Hook**: Probes `phantom_lattice.has_pending_latches(&doc.gid)`.
       If true, pops all waiting shadow records and atomically fuses them into active
       relationships within the same group-commit epoch.

3.3 Cold-Start Latch Warmup (storage/src/python.rs)
  - Upon server boot or engine initialization (`CleaveDB::new()`):
    Scans persistent `_bonds` bucket entries across all storage shards.
    Identifies any records with `status == "latched"` and re-populates the in-memory
    `PhantomLattice` and counting filter.
  - Result: Late-binding bonds survive server restarts with full in-memory reactivity.

3.4 Volcano Execution Engine (storage/src/engine/volcano.rs)
  - `LateBindingJoinNode`:
    A pull-based iterator node that joins child documents with parent targets.
    When `allowing_unresolved` is active, it yields virtual tuples tagged with:
    `_virtual_bond: { "status": "latched", "target_gid": ... }`
  - `ShadowScanNode`:
    Scans unmaterialized shadow records directly from the Phantom Lattice for audits.

3.5 Generational Sweeper & Index Healer (storage/src/engine/heal.rs)
  - `sweep_expired_bonds()`:
    Scans the Phantom Lattice for firm bonds whose lease window has elapsed.
    Evicts expired shadow latches and updates telemetry.
  - `heal_all()`:
    Rebuilds inverted indices and cleans up broken references while explicitly
    preserving latched late-binding bonds from premature deletion.

3.6 CleaveQL Interpreter & Grammar (cleaveql/interpreter.py & parser.py)
  - `_validate_doc_and_bucket()`:
    Added `allow_unmaterialized=True` for late-binding bond declarations.
  - `BondStmt`:
    Creates latched bond records in `_bonds` when targets have not arrived.
  - `PourStmt`:
    Executes the Python-level Cleave-Snap hook: updates waiting latched bonds in `_bonds`
    from `"latched"` to `"active"` with `fused_at` timestamps upon target document arrival.
  - `FIND / SCOOP`:
    Traversals over candidate/unresolved bonds return typed virtual pending nodes.
  - `ShowStmt`:
    Added native support for `SHOW PENDING [BONDS]`, `SHOW PHANTOM`, and `SHOW LATCHES`.

3.7 Tarjan's Phantom Cycle Detector (cleaveql/interpreter.py)
  - Added `SHOW CYCLES` and `SHOW PHANTOM CYCLES`.
  - Implements Tarjan's Strongly Connected Components (SCC) algorithm across both
    materialized and unmaterialized bond edges.
  - Reports directed cycles, cycle lengths, and identifies whether any cycles involve
    unmaterialized phantom targets.

5. USER-FACING CLEAVEQL SYNTAX & COMMANDS
--------------------------------------------------------------------------------
1. Declare a Late-Binding Bond (target does not exist yet):
   BOND "orders:ord_101" TO "customers:c42" AS "purchased_by"
   --> Status: ok (1 Graph Bond 'purchased_by' created (1 latched pending target arrival).)

2. Inspect Pending Shadow Latches:
   SHOW PENDING
   SHOW PENDING BONDS
   --> Returns: [ { source: "orders:ord_101", target: "customers:c42", status: "latched" } ]

3. Traverse Relationships Allowing Unresolved Targets:
   FIND CANDIDATE "purchased_by" OF "orders:ord_101"
   --> Returns virtual node: { _status: "pending_unmaterialized", target_gid: "customers:c42" }

4. Ingest Target Document (Triggers Cleave-Snap):
   POUR INTO customers "c42" {"name": "Alice Smith", "tier": "Gold"}
   --> Bond automatically snaps into "active" with fused_at timestamp!

5. Traverse Materialized Fused Graph:
   FIND "purchased_by" OF "orders:ord_101"
   --> Returns Alice Smith's document as a direct graph hop!

6. Detect Topological Cycles:
   SHOW CYCLES
   SHOW PHANTOM CYCLES
   --> Returns: { "cycles_detected": 0, "cycles": [] }

7. Reconcile Broken Data and Sweep Expired Leases:
   HEAL BONDS
